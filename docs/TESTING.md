# Проверка чтения и обновления PWA

## Автоматические проверки

```sh
npm ci
npm test
npm run build
node scripts/check-content.mjs
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Сборка дополнительно проверяет, что все UI JS/CSS/шрифты/изображения попали в precache ровно один раз, код Workbox включён в сам worker, а тексты книг и API не кешируются как оболочка.

Веб-тесты проверяют данные IndexedDB, переход схемы v1 → v2, историю позиции прежнего издания, чтение проверенного текста из Cache Storage после повторного открытия базы, обрыв повторной загрузки, повреждение/удаление кеша, digest и структуру текста. Тесты жизненного цикла PWA проверяют однократную регистрацию и защиту открытой читалки от обновления, активированного в другой вкладке. Эти тесты не заменяют браузерную проверку service worker.

## Первая установка и запуск без сети

Использовать production-сборку: `npm run preview`. В dev-режиме worker отключён.

1. Открыть `/settings` на новом локальном порту или в чистом профиле браузера. Дождаться «Приложение сохранено на устройстве».
2. Открыть каталог, карточку тестовой книги, скачать и дождаться кнопки удаления загрузки. Прогресс 100% возможен только после проверки размера, SHA-256 и структуры.
3. Остановить preview-сервер, не открывая читалку заранее. Открыть её из карточки: это проверяет не только текст книги, но и ленивый chunk читалки.
4. Перейти во вторую главу, поставить закладку, перезагрузить страницу. Глава и закладка должны восстановиться при остановленном сервере.
5. Открыть новую вкладку с прямой ссылкой `/read/room-for-stories`. Она должна запуститься без сервера и восстановить данные.
6. Открыть `/downloads`, прочитать текст, удалить только загрузку. Позиция и закладки остаются. Попытка читать удалённый текст без сети показывает понятную ошибку.

Повторить на настоящих Android и iPhone, в установленной PWA и авиарежиме. Проверить закрытие браузера/приложения, перезапуск телефона, нехватку места и очистку браузером кеша. Localhost компьютера не доступен телефону как localhost — нужен HTTPS-стенд.

## Обновление приложения

1. Открыть читалку в первой вкладке и каталог во второй.
2. Собрать изменённую версию приложения, перезагрузить только вторую вкладку, дождаться предложения обновить.
3. Применить обновление во второй вкладке. Первая вкладка с читалкой не должна перезагружаться.
4. В первой вкладке сохранить и выйти, затем явно применить обновление. После перезагрузки восстановить главу/абзац и закладки.
5. Если издание книги обновлено, прежний locator должен остаться в IndexedDB `positionHistory`; новый текст открывается с первой главы. Закладки прежней версии не должны переносить пользователя по неверным ID нового текста.

Версия схемы IndexedDB, версия книги и версия service worker — независимые вещи. Для будущих несовместимых изменений нужна дополнительная проверка нескольких одновременно открытых версий приложения.

## Незавершённое ручное сохранение места аккаунта

`position-choices.test.ts` проверяет сохранение точного payload/operation ID в IndexedDB v4, повтор после потери ответа и открытия базы заново, запрет повтора при конфликте ревизий, истёкшую сессию, смену аккаунта, конкурирующий выбор и отказ записи. Миграция из v3 сохраняет позиции и outbox; подтверждение ручного выбора не удаляет более поздние изменения чтения.

Для ручной проверки нужны работающие API/БД и вход по почте:

1. В профиле сравнить место устройства и аккаунта. Отключить сеть перед сохранением и нажать сохранение. Закрыть диалог и перезагрузить страницу.
2. Восстановить сеть и подтвердить вход тем же аккаунтом. В разделе мест чтения открыть незавершённое сохранение: выбранная глава/абзац и прежнее место аккаунта должны соответствовать исходному сравнению. Самостоятельной отправки при входе быть не должно.
3. Повторить сохранение. Если первый запрос уже был принят, повтор должен вернуть тот же результат без дополнительной серверной ревизии. Более позднее место чтения на устройстве и его outbox должны сохраниться.
4. Изменить серверное место со второго устройства до отправки исходного выбора. Получить конфликт; после перезагрузки повтор исходного выбора должен оставаться заблокированным. Отменить выбор, дождаться загрузки мест и сравнить заново.
5. Выйти при незавершённом сохранении: должно появиться предупреждение. Войти другим аккаунтом: сохранение первого аккаунта не отображается. После возвращения в исходный аккаунт оно снова доступно.

Это сценарий ручного сохранения места. Автоматический обмен outbox и офлайн-вход в аккаунт остаются отдельными задачами. Браузерный сценарий с живым API не подтверждается одними unit-тестами.


## Статус сохранения аккаунта

`account-save-status.test.ts` проверяет отдельный подсчёт мест, изменений закладок (включая удаления), записей времени и других изменений, а также приоритет конфликтов/неподтверждённых сохранений и изоляцию аккаунтов от гостя. Пустая очередь не называется синхронизированной.

`position-choices.test.ts` дополнительно проверяет подтверждение конкретных operation IDs, повтор без расширения набора подтверждаемых записей, новое чтение во время запроса, отказ локальной транзакции после серверного успеха и совместимость с ранее сохранёнными выборами без списка operation IDs.

1. Войти в аккаунт с пустой локальной очередью, открыть профиль. Блок «Сохранение данных» должен показывать «Нет изменений, ожидающих отправки».
2. Открыть читалку аккаунта, поставить закладку, читать и сохранить/выйти. В профиле должны появиться «Сохранено на устройстве» и отдельные количества мест, изменений закладок и записей времени. Гостевые изменения в этот блок не входят.
3. Явно сохранить место аккаунта в разделе ниже. Подтверждённое изменение места исчезает из счётчика; закладки и время остаются. Если чтение продолжалось после начала сохранения, новое место остаётся в очереди.
4. Повторить с потерей ответа и перезагрузкой. Блок показывает неподтверждённое сохранение; повтор отправляет прежний вариант. При конфликте показывает необходимость сравнить места заново. Отмена повтора не очищает локальные изменения.
5. Выйти и войти другим аккаунтом. Статус и счётчики должны соответствовать только текущему аккаунту. При недоступном хранилище нельзя показывать пустую очередь как успешную проверку.
