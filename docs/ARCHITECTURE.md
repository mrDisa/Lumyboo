# Архитектура первого среза

- `apps/web`: React, TypeScript, Vite; TanStack Router с прямыми ссылками, TanStack Query для загрузки текста. Читалка загружается отдельным chunk. CSS-токены и графика извлечены из утверждённого прототипа; новые правила вынесены отдельно, стили читалки — CSS Module.
- `services/api`: модульный монолит Go/chi. `/healthz` — живой процесс, `/readyz` — доступность PostgreSQL. `/api/v1/catalog` — локальные фикстуры с поиском и пагинацией. Вход по email-коду и серверные сессии реализованы: текущий аккаунт доступен только по HttpOnly-cookie, изменяющие запросы защищены Origin и сессионным CSRF-токеном. Коды и токены хранятся хешированными; попытки, доставка и отзыв сессий проверяются на PostgreSQL.
- `contracts/openapi.yaml`: источник типов для `api.generated.ts`. Тип Book и заготовка клиента используют сгенерированный контракт.
- Веб пока читает **локальный manifest каталога**, а не API. Это позволяет проверять офлайн-сценарий до реализации серверного редакционного каталога. API seed соответствует manifest; `scripts/check-content.mjs` проверяет совпадение.
- Dexie v3 (миграции из v1/v2 без удаления данных): настройки, полка, позиции, закладки, загрузки, локальные сессии. Данные одного гостевого браузера; вход в серверный аккаунт пока не переносит их и не меняет владельца. Не использовать этот namespace для аккаунтов без LUM-028/033.
- Cache Storage `lumyboo-books-v1`: только явно скачанные общедоступные технические тексты. SHA-256 и версия проверяются перед записью и чтением. После очистки браузером отметка загрузки снимается при запуске или открытии текста.
- Workbox precache: оболочка, локальные шрифты и изображения. Тексты книг не включены в precache. `/api/` не кешируется; нет общего runtime-кеша авторизации и приватных ресурсов.
- Позиция: версия, номер главы, ID абзаца, доля прокрученной высоты абзаца. Перестройка текста не превращает экранную страницу в ID. Прежний locator при смене издания архивируется. Автоматическое сопоставление абзацев разных изданий и конфликты между устройствами ещё не реализованы.
- Локальные сессии: monotonic clock, запись накопленного значения под одним UUID. Повторный snapshot заменяет предыдущий, а не добавляет секунды. Временные разрывы >5 с не начисляются; пограничные случаи при подвисании/блокировке требуют устройства. Нет XP, покрытия, статуса «прочитано» и серверного доверия к этим данным.
- Worker — явно не реализован; команда завершается с объяснением. River/sqlc/S3-клиент добавляются вместе с первыми реальными потребителями, не имитируются пустым процессом. PostgreSQL/MinIO подготовлены в compose.

## Техническая проверка EPUB (LUM-017/018, частично)

Для первого сценария выбрана нормализация доверенных редакционных EPUB в текстовый JSON: браузер отображает строки средствами React и никогда не вставляет HTML книги. Импортёр использует стандартную библиотеку Python, проверяет archive traversal, дубли, размер, symlink, шифрование, DTD/entities и внешние spine-ресурсы. Скрипты и неподдерживаемый мультимедийный контент отклоняются.

Поддержаны линейные XHTML-главы, кириллица, заголовок главы, абзацы и текст простого inline-форматирования. В этом срезе inline-начертание нормализуется в обычный текст. Изображения, таблицы, SVG, математическая разметка и интерактивные сноски **не поддержаны**. Универсальная поддержка EPUB не заявляется. Требуется дальнейшая проверка на 5–10 книгах; движок/нормализатор ещё не признан окончательно подходящим для всего каталога.

Исходник тестовой книги: `content/fixtures/room-for-stories.epub`. Его импорт даёт байт-в-байт тот же JSON, который открывает приложение. Импортёр не публикует книгу и всегда выдаёт `rights_status: pending`: редакторская запись не является автоматической проверкой прав.

## Защита офлайна и обновления

Worker самодостаточен: Workbox runtime встроен, внешних importScripts нет. Первая установка использует clientsClaim; skipWaiting остаётся выключенным до явного применения обновления. Публичные ресурсы с постоянными именами имеют content revision; дубли precache устранены. Регистрация выполняется singleton-модулем, а не побочным эффектом React initializer.

Обновление, активированное другой вкладкой, не вызывает автоматическую перезагрузку читалки. Перезагрузка выполняется по запросу пользователя вне читалки. Настройки показывают проверенное наличие оболочки и активного controller.

Загрузка текста читает поток с контролем размера, показывает процент, затем проверяет SHA-256 и обязательные chapter/paragraph IDs. Неудачный повтор не удаляет ранее проверенную копию. Сверка загрузок удаляет ложные отметки после очистки или повреждения кеша. Раздел `/downloads` доступен без сети и позволяет удалить текст, оставив личные данные чтения.

При смене издания прежняя позиция архивируется транзакционно в `positionHistory` до записи новой. Закладки предыдущих версий сохраняются в базе, но не используются как locator нового издания.

## Локальная очередь изменений

Изменения полки, настроек, позиций, закладок (включая удаление) и snapshots времени записываются вместе с outbox одной транзакцией IndexedDB. Ошибка очереди откатывает изменение. Операция содержит UUID, версию формата, постоянный случайный ID установки, монотонную последовательность и явную область `guest`. ID установки не является ID пользователя и не даёт прав на сервере.

Очередь хранит последний ещё не отправленный snapshot каждой сущности; удаление остаётся отдельным tombstone. Операции в состоянии `sending` не изменяются: будущий отправитель должен пометить выбранный пакет этим состоянием транзакционно до сетевого запроса и повторять его с прежними ID до подтверждения. Последовательность задаёт локальный порядок, а не серверную версию и не приоритет при конфликте. Время сессии передаётся накопленным значением, а не прибавлением секунд.

Отправителя и серверного приёма пока нет. Вход не привязывает гостевую очередь к аккаунту. Старые данные при миграции остаются локальными и не превращаются автоматически в операции: их включение в перенос требует отдельного подтверждённого сценария LUM-033. Кеши загрузок и история старых изданий в очередь не входят. Данные читаются непосредственно из локальных таблиц, поэтому накопление очереди не блокирует офлайн-чтение; ошибка её записи обрабатывается как ошибка сохранения.

## Явное копирование гостевой полки (LUM-033, первый срез)

`GET /api/v1/shelf/` читает полку только текущей серверной сессии. `POST /api/v1/shelf/import` принимает явный список книг и ожидаемый account ID: владелец определяется по cookie, а несовпадение ожидаемого ID отклоняется. Запрос защищён Origin/CSRF; ответы `no-store`. Доступные ID проверяются по текущему локальному каталогу пилота, не по произвольным данным клиента.

Копирование выполняется одной PostgreSQL-транзакцией. Блокировка пользователя сериализует его импорты; `ON CONFLICT DO NOTHING` сохраняет имеющиеся книги и делает повтор после утраты ответа безопасным. Схема `shelf` уже существует, новая миграция не требуется. Это идемпотентность добавления книг, а не общий протокол обработки outbox/серверных ревизий по LUM-035.

В профиле серверная полка показана отдельно от гостевой. Копирование требует подтверждения списка и email; не удаляет и не меняет локальные данные. Кеш запроса разделён по аккаунту, уничтожается после отключения подписчика, а ответ другого аккаунта отклоняется. При проверке/ошибке сессии блок аккаунта скрыт. Прогресс и закладки остаются гостевыми; гостевая очередь не отправляется и не привязывается к cookie. Полный account namespace, перенос закладок/позиций, конфликты и автоматическая синхронизация остаются следующими задачами.
