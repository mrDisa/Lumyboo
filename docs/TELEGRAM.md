# Telegram Mini App

Публичная точка входа лендинга: `https://t.me/lumyboo_bot?start=app`. Ссылка настраивается публичной переменной сборки `VITE_TELEGRAM_APP_URL`; бот-токен в веб-сборку не передаётся. Само приложение открывается по HTTPS на маршруте `/app`. Telegram запускает веб-приложение внутри своего клиента; отдельный файл APK/IPA не нужен.

## Бот

`services/api/cmd/telegram-bot` использует официальный Bot API без дополнительных библиотек. При старте проверяет бота через `getMe` и задаёт кнопку меню «Читать» с `web_app`. В личном чате команды `/start` и `/help` получают приветствие и кнопку «Открыть Lumyboo». Группы, посторонние сообщения и данные Web App не обрабатываются. Telegram ID не используется для входа в аккаунт: сохраняется существующий вход по email внутри приложения.

Настройки процесса:

- `TELEGRAM_BOT_TOKEN` — секрет из окружения хоста, не из `VITE_*` и не из исходников.
- `MINI_APP_URL` — реально развёрнутый HTTPS-адрес приложения, например `https://your-domain.example/app`, без учётных данных и fragment.

```sh
cd services/api
# Перед запуском задайте переменные через секреты хоста.
go run ./cmd/telegram-bot
```

Образ — `services/api/Dockerfile.telegram`. В комплекте стенда процесс включается отдельным профилем:

```sh
docker compose --env-file ops/staging/.env -f ops/staging/compose.yaml \
  --profile telegram up -d --build telegram
```

Один экземпляр процесса получает события long polling; публичный webhook и входящий порт не требуются. Не запускайте одновременно второй poller или другой webhook-обработчик того же бота. Остановка процесса останавливает ответы; для постоянного бота нужен работающий хост.

## Перед включением

Сначала разверните приложение на выбранном HTTPS-домене. Закрытый staging с Basic Auth потребует входа также внутри Telegram; для публичного Mini App нужен соответствующий публичный выпуск, а не снятие защиты с тестовой базы. Проверьте открытие `/app` в Telegram на Android/iPhone, вход по email, возврат из фона и доступ к скачанным книгам именно в этом WebView. Проверка сайта в обычном браузере их не заменяет.

Ссылка `?start=app` ведёт к кнопке бота и не требует регистрации Main Mini App. Если нужна отдельная кнопка «Открыть приложение» в профиле бота и запуск по `?startapp`, настройте Main Mini App через BotFather после размещения; затем обновите `VITE_TELEGRAM_APP_URL` и пересоберите веб.

Официальные контракты: [Mini Apps](https://core.telegram.org/bots/webapps), [Bot API](https://core.telegram.org/bots/api). Секретные токены и тексты сообщений в журналах процесса не выводятся.

## GitHub Pages без сервера

Сборка `npm run build:pages -w apps/web` размещается в `/Lumyboo/` и использует hash-маршруты. Для кнопки Telegram задайте `MINI_APP_URL=https://mrdisa.github.io/Lumyboo/?app=1`: входная страница направит в `#/app`. Сначала необходимо опубликовать и проверить этот адрес.

После публикации можно один раз запустить `go run ./cmd/telegram-bot --configure-only` с секретом из окружения. Кнопка меню сохраняется у Telegram и открывает статическое приложение без постоянно работающего процесса. Ответы на `/start` и `/help` требуют работающего poller; на GitHub Pages он не запускается. Main Mini App в профиле бота настраивается отдельно через BotFather. В Pages доступны только гостевые данные на устройстве; вход по email и челленджи отключены.

Текущий публичный адрес: `https://mrdisa.github.io/Lumyboo/?app=1`. У `@lumyboo_bot` сохранена кнопка меню «Читать» с этим URL. Команды и приветствие обслуживаются Supabase webhook; Go poller для этого выпуска не запускается. Запуск самого Telegram WebView и установка на физических устройствах требуют отдельной приёмки.

## Объёмный знак и полноэкранный запуск

Единый знак хранится в `apps/web/public/assets/sculpture.svg`. `npm run brand -w apps/web` создаёт повёрнутый брендовый знак, favicon и иконки PWA 180/192/512 px; экспорт для Telegram — `brand/lumyboo-telegram-avatar.png` (1024 px). JPEG-версию для Bot API можно получить обычным преобразованием формата; аватарка бота обновляется методом `setMyProfilePhoto`.

При запуске из Telegram приложение загружает официальный JS bridge до инициализации hash-маршрутов, вызывает `ready`, `expand` и `requestFullscreen` для клиентов 8.0+. Экран учитывает safe-area и кнопки Telegram; на десктопе обычного браузера компактная рамка сохраняется. `/?app=1&view=profile` открывает профиль, `view=catalog` — каталог. Вне Telegram bridge не загружается. Нативный полноэкранный режим зависит от версии/платформы клиента и требует проверки в самом Telegram.

Обработчик для Supabase Edge Functions: `supabase/functions/telegram-bot/index.ts`. Он обрабатывает `/start`, `/read`, `/catalog`, `/profile`, `/help` только в личном чате, возвращает приветствие и кнопки читалки/каталога/профиля. Для работы нужны секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` и Telegram webhook с тем же `secret_token`. Проверка Supabase JWT для этой функции заменяется обязательной проверкой секретного заголовка Telegram; без секретов обработчик отвечает 503, с неверным заголовком — 403. Тексты сообщений и секреты не журналируются. Не запускайте Go poller одновременно с webhook.

Pages теперь открывает прежний локальный профиль: имя, гостевая полка, дневная цель, история и закладки устройства. Это не подключает облачный аккаунт: существующий Go API, его PostgreSQL и доставка кодов входа должны быть размещены отдельно либо перенесены на Supabase с сохранением проверок доступа и правил синхронизации.

Обработчик `telegram-bot` размещён в проекте Supabase `knbchbcoispqemrvwntf`; токен и секрет вебхука сохранены в секретах проекта. Telegram webhook направлен на `https://knbchbcoispqemrvwntf.supabase.co/functions/v1/telegram-bot`. Аватарка, описание и пять команд бота обновлены через Bot API. Для проверки отправьте `/start` в личном чате `@lumyboo_bot`; группы и обычные сообщения обработчик игнорирует.
