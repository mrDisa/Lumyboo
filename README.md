# Lumyboo

PWA для чтения с утверждённым дизайном Blanc/Noir. На компьютере приложение сохраняет компактную рамку телефона. Это локальный пилот, не готовый публичный сервис.

## Запуск веб-приложения

Нужны Node.js 24+ и npm. Проверено на Node.js 26.7 / npm 11.19.

```sh
npm ci
npm run dev
```

Vite покажет локальный URL. В dev-режиме service worker отключён. Для проверки PWA:

```sh
npm run build
npm run preview
```

Открыть `http://127.0.0.1:4173`. В каталоге открыть тестовую книгу, скачать её, затем читать. Service worker работает на localhost или HTTPS. Для телефона нужен HTTPS-стенд; localhost компьютера не является localhost телефона.

Одна книга в рамках одного гостя или аккаунта открывается для чтения только в одной вкладке этого браузера. Во второй вкладке нужно повторить открытие после сохранения и выхода из первой: место и закладки загрузятся заново. Нужен браузер с Web Locks и HTTPS (либо localhost); если безопасная блокировка недоступна, читалка не открывается. Это локальная защита вкладок одного origin, а не синхронизация устройств.

## API и локальная инфраструктура

Нужны Go 1.26+ и запущенный Docker Desktop.

```sh
docker compose -f ops/compose.yaml up -d
# Применить миграцию; состояние БД не удаляется:
for migration in services/api/db/migrations/*.up.sql; do
  docker compose -f ops/compose.yaml exec -T postgres psql -U lumyboo -d lumyboo -v ON_ERROR_STOP=1 < "$migration"
done
export DATABASE_URL='postgres://lumyboo:local-development-only@127.0.0.1:5432/lumyboo?sslmode=disable'
npm run api
```

API: `http://127.0.0.1:8080/healthz`, `/readyz`, `/api/v1/catalog?q=Достоевский&limit=20&offset=0`. Без DATABASE_URL API каталога доступен, readiness возвращает 503. MinIO: `http://127.0.0.1:9001`, реквизиты только для разработки — в `ops/compose.yaml`. Веб пока использует локальный каталог; интеграция серверного каталога впереди. Worker/River ещё не реализован.

Compose не создаёт бакет автоматически; использование S3 появится с серверным импортом. Контейнер API можно собрать из `services/api/Dockerfile`. Секреты production не помещать в `.env.example` или compose.

## Вход по почте (локальная проверка)

В `ops/compose.yaml` есть Mailpit: SMTP `127.0.0.1:1025`, тестовый ящик `http://127.0.0.1:8025`. Письма не отправляются реальным получателям. Для входа примените все миграции и запустите API с настройками из `.env.example`:

```sh
cp .env.example .env
set -a
. ./.env
set +a
export AUTH_SECRET="$(openssl rand -base64 32)"
npm run api
```

В отдельном терминале: `npm run dev`, затем `/login`. `PUBLIC_ORIGIN` должен точно совпадать с адресом Vite. Пустой `AUTH_SECRET` оставляет вход отключённым. Коды живут 10 минут, имеют 5 попыток; повторная отправка — не чаще раза в минуту, дополнительно действуют общие лимиты по email/IP. Для production нужен постоянный секрет в защищённой конфигурации, HTTPS и SMTP с обязательным STARTTLS; провайдер ещё не выбран. Plaintext SMTP разрешён только на loopback в development. За reverse proxy нужно явно настроить `TRUSTED_PROXY_CIDRS`; заголовок X-Forwarded-For от остальных источников игнорируется. После входа профиль показывает полку аккаунта. Кнопка «Скопировать гостевую полку» открывает список книг и аккаунт назначения; подтверждение добавляет книги на сервер, сохраняя прежнюю полку аккаунта и локальные данные. Повтор безопасен. В том же профиле можно выбрать до 100 гостевых закладок и скопировать их в аккаунт. Существующие закладки и удаления аккаунта имеют приоритет; локальные данные сохраняются. Книги из серверной полки открываются в отдельной читалке аккаунта с его закладками. В блоке «Места чтения аккаунта» можно сравнить место устройства с серверным и явно сохранить нужный вариант в аккаунте. Если место успело измениться с другого устройства, сравнение нужно открыть заново. Прежний вариант сохраняется в серверной истории; повтор запроса безопасен. Отдельная кнопка «Сравнить и принять место на устройство» показывает место текущего аккаунта на устройстве и выбранный серверный снимок. После подтверждения прежнее место устройства архивируется, а только показанные изменения позиции снимаются с ожидания отправки. Более позднее чтение требует нового сравнения; читалку книги нужно закрыть во всех вкладках. Гостевые места, закладки и время не затрагиваются. Для приёма повторно проверяется вход; серверный снимок сам по себе не подтверждает актуальность всех данных. При открытии читалки аккаунта приложение загружает серверное место и сравнивает его с локальным местом этого аккаунта. При различии выбор явный; прежний локальный вариант архивируется при выборе серверного. Гостевые позиции, закладки и минуты остаются отдельно. При выходе есть предупреждение о неотправленных изменениях. Повторное открытие аккаунта требует сети для проверки входа; офлайн-доступ без проверки сессии пока не реализован. В профиле видны локальные изменения, незавершённые сохранения и конфликты мест чтения. Успешное ручное сохранение подтверждает только ранее выбранную позицию: более позднее чтение, закладки и время остаются в очереди. Пустая очередь не подтверждает актуальность всех серверных данных. Автоматического обмена пока нет. Серверный протокол изменений закладок с ревизиями, удалениями и безопасными повторами доступен через `GET /api/v1/bookmarks/state` и `POST /api/v1/bookmarks/apply`; В разделе «Сохранить изменения закладок» можно сравнить закладку аккаунта на устройстве с серверным вариантом, явно сохранить её (в том числе восстановить ранее удалённую) или удалить серверную закладку. Перед запросом выбор сохраняется на устройстве: неподтверждённое изменение можно открыть после перезапуска и повторить. Конфликт требует отмены повторов и нового сравнения. Сохранение и удаление в аккаунте не меняют локальную закладку. Отдельная кнопка «Сравнить и принять на устройство» позволяет явно получить выбранный вариант аккаунта или его удаление. Подтверждение заменяет локальную закладку и снимает только её показанные изменения с ожидания отправки; более поздняя правка требует нового сравнения. Перед принятием проверяется вход, читалку этой книги нужно закрыть во всех вкладках. Автоматическая отправка очереди пока не подключена.

Если загрузка серверных мест или закладок завершилась ошибкой, читалка предлагает явно продолжить с места аккаунта на устройстве. Откроется только уже сохранённое место текущего издания; местные закладки и очередь изменений сохраняются. Перед открытием повторно проверяется вход: без сети, при истёкшей сессии или смене аккаунта этот способ недоступен.

## Импорт тестового EPUB

```sh
python3 scripts/import_epub.py content/fixtures/room-for-stories.epub \
  --id room-for-stories --version 1 \
  --output /tmp/room-for-stories.json \
  --rights-basis 'Original development fixture'
```

Импортёр пока поддерживает простой текстовый EPUB. Выводит размер и SHA-256; не публикует книгу. Список ограничений — в `docs/ARCHITECTURE.md`.

Документы: [архитектура](docs/ARCHITECTURE.md), [проверки чтения и PWA](docs/TESTING.md). План, внутренние журналы разработки и исходный дизайн-прототип хранятся локально и исключены из Git.

Сервер принимает накопительные отчёты времени через `POST /api/v1/reading-sessions/apply`; актуальную запись своего аккаунта можно получить через `GET /api/v1/reading-sessions/{sessionId}`. Повторы операции безопасны, запоздалые снимки не уменьшают время и не складываются с новыми. Устройство, книга, издание и заявленный день сессии неизменны. Это непроверенные клиентские отчёты, без начисления дневных целей, XP, серий и завершения книг. Новые сессии веб-таймера фиксируют устройство и издание; кнопка «Сохранить время в аккаунте» в профиле явно отправляет до 50 записей. Неподтверждённые запросы переживают перезапуск и повторяются с тем же UUID и данными. Более позднее чтение остаётся в очереди. Старые сессии без этих метаданных остаются локальными; гостевое время не отправляется. При открытом приложении записи времени текущего аккаунта отправляются автоматически: при входе, возвращении сети и проверке очереди каждые 30 секунд. Перед каждым пакетом проверяется живая сессия; временные ошибки повторяются с задержкой 5 секунд — 5 минут (с учётом Retry-After), ошибки входа/конфликты/ошибки локального подтверждения останавливают автоповторы до повторной проверки входа или успешного ручного сохранения. Закрытие приложения отменяет запрос, оставляя точный снимок для повтора. Позиции и закладки по-прежнему требуют явного выбора. Контракт — в `contracts/openapi.yaml`, воспроизводимые проверки — в `docs/TESTING.md`.

В «Время чтения аккаунта» можно раскрыть «Сохранённое время с устройств»: история загружается из аккаунта по 20 записей с переходами между страницами и обновлением с начала. Показываются книга, длительность и день по часам устройства. Полученная история не прибавляется к локальному счётчику минут. Список содержит только отправленные записи; новые сохранения видны после обновления. API: `GET /api/v1/reading-sessions/?limit=20&cursor=…`. Для истории примените миграцию 007 с индексом пагинации.

Фрагменты показанного текста аккаунта также сохраняются автоматически при открытом приложении: проверка очереди каждые 30 секунд, безопасный повтор точного запроса после сетевого сбоя, остановка при ошибке входа или подтверждения. Профиль показывает статус и позволяет повторить сохранение вручную. При открытии читалки аккаунта фрагменты этого издания автоматически дополняются данными из аккаунта, не задерживая чтение. После успешного получения новое запускается при возвращении в читалку или восстановлении сети, включая случай прежней пустой истории. Пока читалка видима и имеет фокус, успешное получение также обновляется раз в минуту при наличии сети. Временные ошибки повторяются с задержкой, выход из читалки отменяет запрос и периодические обновления. Возвращение и восстановление сети не обходят задержку или остановку после ошибки входа/проверки данных; повтор доступен в профиле. Кнопка в профиле также позволяет получить фрагменты выбранной книги вручную. Эти данные сами по себе не подтверждают полное прочтение книги.

В оглавлении читалки для каждой главы показаны количества абзацев, сохранённых целиком, частично и ещё не показанных. Сводка относится к текущему изданию и текущему гостю или аккаунту; она обновляется после сохранения местных или получения серверных фрагментов. Пропущенные участки остаются пропущенными. Эти счётчики описывают появление текста на экране, а не подтверждённое прочтение или завершение книги.
